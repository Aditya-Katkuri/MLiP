WHAT WAS RECONSTRUCTED

The only surviving original SIFT script scored three classes on an older dataset.
Its SIFT extraction, codebook fit, histogram construction, and prototype functions
were reused without modification. The adapter changes data parsing to the current
five-class processed dataset and adds predictions, hazard scoring, and evidence.
The old script and unrelated shared-repository files were left unchanged.

The report did not identify the training split, and its 380-image SIFT prediction
export was missing. Therefore two training pools were specified before looking
at test results. Neither variant was chosen by maximizing test performance:
  pitt_only: pitt-train only; 999 fitted images, 553 codebook images.
  pooled_other_and_pitt: concatenate other-cities-train then pitt-train;
    sample at most 500/class from that pool, for 2,429 fitted images and 1,000
    codebook images. This is pooled sampling, not sequential fine-tuning.

Both use the same fixed settings: random.Random('sift-tagger-v1-<class>') shuffles
CSV-ordered class pools; first 500/class form prototypes, first 200/class contribute
to the shared codebook, or all available images when fewer. SIFT requests 40 sparse
features plus up to 40 dense-grid descriptors every 32 px, with a total 80-descriptor
cap. OpenCV may return more than 40 sparse features on response ties; the original
80-total truncation is preserved exactly. Existing 224x224 images are converted
to grayscale. Codebook: 200 visual words, kmeans++ seed 0, 1 attempt, max 20 iterations,
epsilon 0.1. Prototypes are means of per-image L1 histograms, L1-normalized again.
Distance is symmetric chi-square: 0.5*sum((h-p)^2/(h+p)) over nonzero denominators.

All five classes are included: Crosswalk, CurbRamp, Obstacle, SurfaceProblem,
no_obstacles. Hazards are Obstacle and SurfaceProblem. Hazard ranking score is
min(clean distances)-min(hazard distances), as in the report. A positive margin
means hazard; zero is non-hazard. Scores/distances are not probabilities.
Top 46 ties use SHA256(image bytes), independent of the ground-truth directory.
Subtype is the nearer of the two hazard prototypes; exact ties choose Obstacle.
Nearest-five-class exact ties favor clean, then the documented class order.
There was no validation/test tuning, and no test/validation image was used to fit.

Its five-class accuracy is 78/380=20.5263%. Hazard precision@46 and overall
five-class accuracy measure different behaviors and must not be interchanged.

WHY THE PER-CLASS RESULTS MATTER

The pooled SIFT classifier strongly favors Obstacle at the subtype decision:
109 of 146 true hazards are assigned Obstacle, although only 16 are actually
Obstacle. Its high Obstacle recall accompanies very poor precision and poor
SurfaceProblem recall. This supports reporting precision/recall/F1 for each
class rather than relying only on balanced accuracy. Use the exported confusion
matrices for counts; minority-class estimates have only 16 Obstacle test records.

VALIDATION AND LIMITS

All four manifest hashes match the previously downloaded evidence. Every test
image byte hash matches the GPT experiment. The 380 test records contain 368
distinct byte hashes; duplicate records are retained for comparison with the
submitted results. All 23,911 training records were byte-hash checked against test:
there are zero train/test identical-byte overlaps. This does not rule out similar
scenes or other forms of spatial correlation. Validation images were not scored.

All 30 downloaded artifacts passed archive/checksum validation. Local independent
checks reconstructed distances from saved histograms/prototypes, checked that
each prototype is exactly the mean of the selected training histograms, verified
rankings and score signs, and reproduced all confusion matrices and per-class
metrics with scikit-learn. See derived/sift_rerun_verification.json.

The run used OpenCV 4.12.0, NumPy 2.4.6, Python 3.11.15, 16 extraction workers on CPU;
OpenCV kmeans uses 16 threads and BLAS threads were set to 1. Fit/inference/export
took 2.85 s (Pitt only) and 5.25 s (pooled); total job wall time was about 123 s including
the full file/hash audit. No GPU, API call, token, or dependency installation was
needed. This is one deterministic sample/seed per variant, not a robustness sweep.
